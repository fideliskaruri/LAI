# Learning without changing the weights

Press the *next attempt* button on the left. The agent tries to solve a small task &mdash; rearranging the five letters of *TEORS* into a common English word &mdash; and gets it wrong. The verifier tells it so. The agent reflects, in writing, on what it did wrong. The reflection is appended to the prompt, and the agent tries again. Each attempt is one card. Each card shows the guess, the verdict, and the reflection. The accuracy curve on the right pane is what this loop does to a held-out suite of similar anagrams: it climbs from below 20% to nearly 100% across six iterations of *purely verbal* learning.

The paper that introduced this idea is *Reflexion: Language Agents with Verbal Reinforcement Learning*, by Noah Shinn, Federico Cassano, Edward Berman, Ashwin Gopinath, Karthik Narasimhan, and Shunyu Yao &mdash; Northeastern University, with Princeton involvement &mdash; posted to arXiv as 2303.11366 on the 20th of March 2023. The setting is one we have just built up: an agent in a ReAct loop, attempting a task that has a verifier (a unit test, a regex match, a search-engine answer key). When the verifier rejects the agent's first attempt, the agent is asked to *reflect*: write a short paragraph explaining what likely went wrong, what assumption was bad, and what to try next time. That reflection becomes part of the prompt for the next attempt. The model's *weights do not change*. Only the prompt grows.

This is &mdash; let me be careful with the word, because I know "shocking" gets thrown around too freely in this field &mdash; *unreasonable*. We spent chapters 18 through 24 building a giant scaffold for *changing the weights* of a neural network. Backpropagation, optimizers, RLHF, the whole apparatus. And now we are saying that for a sufficiently capable model, you can *learn without any of that*, just by editing the prompt. The model gets better at anagrams not because its parameters shifted but because the prompt it's reading contains a longer and longer list of its own past mistakes and what to do differently. Reflexion's authors named the phenomenon *verbal reinforcement learning*. The phrase is a small joke and a serious technical claim at once. The reinforcement is happening at the *language* level, not the parameter level.

Look at the attempt cards. The first guess, *STERO*, isn't even a word. The reflection is concrete: *STERO is not an English word; I should think about real five-letter words containing T, E, O, R, S.* The second guess, *STORE*, is a real word but uses only four of the five letters. The reflection notices this and adds a constraint: *the anagram requires all five letters.* The fifth attempt re-tries *STORE* (the model has, briefly, lost track of the constraint &mdash; this is a real failure mode and a real thing reflections recover from in practice). By attempt six the model has, in writing, enumerated the alphabetised set of arrangements of T, E, O, R, S, recognised *ROTES* as a real English word (the plural of *rote*), and submitted it. The verifier accepts.

What is happening, mechanically? Each reflection adds a constraint or a heuristic to the model's working memory. *Use all five letters. Don't repeat letters. Be strict about the multiset. Enumerate alphabetically if you can't think of a candidate.* By the sixth attempt, the model has been handed, by its earlier self, a small library of search-heuristics for anagrams. It then applies them. The library lives in the prompt, not in the weights.

This generalises in two ways and breaks in one important way.

It generalises to *any* task where the agent gets a per-attempt signal. Coding problems: the test suite rejects the code; the agent reflects on which test failed and why; the next attempt is informed by the reflection. Web navigation: the agent took a wrong turn; the agent reflects on which click was wrong; the next attempt avoids it. Research: the agent missed a relevant paper; the agent reflects on the search query that should have surfaced it; the next attempt uses the better query. Reflexion is, in this sense, a general algorithm: any agent loop with a verifier can be wrapped in an outer reflection loop, and the inner loop will get monotonically better up to the ceiling the base model can reach.

It generalises to *teams* of agents. If two agents collaborate, each can reflect on the other's mistakes &mdash; what amounts to peer feedback. There are entire research lines on multi-agent reflection (DERA, *Self-Refine*, the various *debater* papers); they all reduce to: more agents writing more reflections about each other, all of which end up in someone's prompt.

It breaks when the *prompt fills up*. The reflections are themselves text; the context window is finite. After enough reflections, the agent can no longer carry them all. Practical systems summarise old reflections into shorter ones, or maintain a separate *reflection memory* indexed by task type (when the agent meets a new anagram, it retrieves the heuristics it wrote down last time it met one), or train a small distilled model on the reflections so the lessons live in weights again. The simple version doesn't scale. The richer versions are what production agents actually do.

A more philosophical observation. Reflexion is, structurally, a very thin form of *introspection*. The model is being asked to look at its own past output and judge it. The model is not very good at this in absolute terms &mdash; it can be made to confidently produce a reflection that's wrong about why the attempt failed &mdash; but it is good *enough* that the outer loop improves on average. We are seeing, in this small example, what *self-correction* looks like in a system that has no actual sensors and no actual stakes. The mechanism scales. The same loop, scaled up, is how a research agent in 2026 reads its own paper draft and notices that the third paragraph contradicts the seventh. The same loop is how a coding agent reads its own code and notices a missing edge case. The reflection is just text. Text is enough.

We have, in five acts, built up the full vocabulary of an agent. A loop. Tools. A plan. Memory. Reflection. The sixth act, before the closing, is about something none of these mechanisms answer: *how much should we let the agent do without asking?*
