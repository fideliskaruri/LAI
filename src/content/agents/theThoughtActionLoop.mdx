# The smallest agent you can build

Press the step button on the left. A line of the trace appears. Press it again. Another line. The trace is the agent's whole life, written out in the order it happened: a sentence of reasoning in plain English, a function call in a structured form, a result coming back, another sentence of reasoning. The right pane shows the same loop in a different register: four stations in a ring &mdash; *model*, *parser*, *tool*, *runtime* &mdash; and a vermilion arc lighting up whichever station is doing work right now. When the model is thinking, the model station glows. When the parser converts the model's words into a structured call, the parser station glows. When the tool runs, the tool glows. When the runtime stitches the result back into the conversation, the runtime glows. Then it's the model's turn again.

This is, technically, what an "agent" is. There is no other definition that matters. An agent is *a language model in a loop where some of its lines are sent out as actions and the results come back as observations*. Everything else &mdash; planning, memory, reflection, tools, autonomy &mdash; is decoration on this single shape.

The example task on the left is comically small. *What's the weather in Berlin in Celsius, and how does it compare to Tokyo?* No human would build an agent for this; you could type "weather Berlin" into your browser and be done. The example is small on purpose. It lets you watch every step of the loop without the loop being lost in the cleverness of the task. Walk through it from the top. The model emits a thought: *I need today's temperature in Berlin and Tokyo. I should look both up, then convert if the units differ.* This thought is not a magic insight; it is the model writing what a competent human would write before reaching for a search box. The thought is followed by an action: `web_search({ query: "weather Berlin today" })`. Notice the shape. The function name is the name of an available tool. The argument is structured JSON. The model has been trained, partly during pretraining and more crucially during a small post-training phase, to emit calls in exactly this format. The runtime parses the call, runs the search, and feeds the result back as an observation: *Berlin · cloudy · 14 °C*. The model writes the next thought, and the loop continues.

What the loop is doing, at a deeper level, is *narrowing the gap between what the model can imagine and what's true.* The model is brilliant at imagining things. Its imagination is its problem. Without external grounding, a model asked for today's Berlin weather will confidently describe a partly-cloudy 12 °C afternoon, because partly-cloudy 12 °C afternoons are extremely typical for Berlin in autumn and the model is, fundamentally, a statistical pattern matcher over training-time text. The ReAct loop fixes this by inserting a *real* tool call between the model and the answer. The tool returns a fact &mdash; the actual temperature, not a typical one &mdash; and the model is now writing its final answer on the basis of a real observation rather than a learned prior. That is the whole point. The agent is a language model with *access*, and *access changes what it can be truthful about*.

A subtlety worth flagging. The thought lines aren't decorative. They look like the model's internal monologue, but they're written *out* &mdash; into the same context window the model will later read. That has two consequences. First, the model's reasoning is auditable. You can scroll back through any agent trace and see, in English, why it chose to call this tool with these arguments. This is not a small thing. Compared with the alternative &mdash; a black-box model that emits actions with no commentary &mdash; the ReAct trace is what makes the agent *debuggable* and, in a meaningful sense, *governable*. Second, because the thoughts go into the context, the model's next turn *reads its own past reasoning*. This is how the agent stays coherent across many steps. It doesn't have to remember what it was doing; it can re-read what it just said about what it was doing. The chain of reasoning becomes a kind of working-memory crutch, written out one sentence at a time.

The version of the loop you're watching is the simplest one. ReAct in its original 2022 form. There are richer versions. Models can emit multiple actions in parallel (Anthropic's tool-use API supports this; the model says *I want to call A and B simultaneously*). Models can spawn sub-agents (the parent agent gives a goal; the child agent runs its own ReAct loop and returns a summary). Models can hold the loop open across days &mdash; pausing for a human approval, resuming when the approval comes. The structural pattern, though, doesn't change. There is always *a turn of reasoning*, *a turn of acting*, *a turn of observing*. Always, always, always. The shape is older than ReAct, by the way. *Yao et al.* names the pattern in the context of language models, but the same loop is what cognitive scientists call the *perception-action cycle*, what control engineers call *closed-loop control*, and what you and I do every time we cook something. Look. Think. Stir. Taste. Adjust. Repeat. The thing that's new in 2022 is that the *thinker* is a transformer and the *world* is a function-call interface to the internet. Everything else is at least as old as the kitchen.

Two acts from now we will let the agent plan over a longer horizon, and two acts after that we will let it reflect on its own failures. But this short loop &mdash; thought, action, observation &mdash; is the whole foundation. Step through the trace one more time. Notice that the model writes more than it acts. Notice that the actions are the load-bearing moments &mdash; without them the model is just talking to itself.
