# The whole architecture, translating one token at a time

Drag the step slider on the left from 0 to 6. As you advance, the French translation emerges one token at a time on the right side of the picture &mdash; *le · chat · &eacute;tait · sur · le · tapis* &mdash; while the cross-attention heatmap on the right pane lights up to show *which English token the decoder is looking at* as it generates each French token. Step three: the decoder is generating *&eacute;tait* and the heatmap is concentrated on the third English token, *sat*. The translation isn't perfect &mdash; *sat* would more idiomatically translate as *s'asseyait* or *&eacute;tait assis*, and a real model trained on real data would prefer those &mdash; but the *attention pattern* is the kind of thing real translation transformers produce.

This is the whole architecture, end to end. The 2017 paper was originally about translation specifically, and the encoder-decoder architecture it proposed has two stacks. The **encoder** reads the source sentence in parallel; every encoder layer is a multi-head self-attention sub-block followed by a feed-forward sub-block, the kind of block we built in the previous act. After *N* = 6 encoder layers, the source sentence has become a sequence of *N*-by-*d* vectors &mdash; one rich, context-laden vector per source position. The encoder is done.

The **decoder** also has *N* = 6 layers, but each decoder layer has *three* sub-blocks instead of two. The first is **masked self-attention**: like ordinary self-attention, but each position is forbidden from attending to any position *to its right*. The mask is just a lower-triangular matrix added to the attention scores before the softmax, with `-Inf` above the diagonal &mdash; the softmax then assigns those positions probability zero. The masking is what makes the decoder *autoregressive*: position *i* in the output can only ever see positions 0 through *i*, never positions to its right. This is what lets the same architecture be used at inference time, when positions to the right *don't exist yet*. The model never had to peek; it was trained never to peek.

The second sub-block is the new one: **cross-attention**. Here the queries come from the decoder's current hidden state, but the *keys* and *values* come from the encoder's output. Each French position asks the encoder, *given what I have been told to write so far, which part of the source matters next?* The cross-attention heatmap on the right is exactly this matrix. It is what allows the decoder to access source information selectively, on a per-output-token basis &mdash; the original problem Bahdanau-Cho-Bengio's 2014 attention bolt-on was invented to solve, now built directly into the architecture.

The third sub-block is the same feed-forward MLP as the encoder. Each decoder layer is, in summary: masked self-attention &rarr; cross-attention &rarr; feed-forward, with residual and LayerNorm wrapped around each.

At inference time, the decoder runs **autoregressively**. You give it a special *start* token; it produces a probability distribution over the vocabulary for what the *first* output token should be; you sample (greedy, beam, or temperature-sampled); you append the chosen token to the decoder's input; you run the decoder again. Each pass produces one new token. You stop when the decoder produces a special *end-of-sequence* token, or when you hit a maximum length. This generation loop is what the step slider on the left is animating &mdash; one slot at a time, the model writes its next token.

A small point about computational cost. Inference is much slower than training, per-token, because each new token requires a forward pass through all the layers &mdash; and each forward pass attends over all previously generated tokens, so the cost of the *k*-th token's generation scales with *k*. Training, by contrast, runs in one shot: you give the model the whole source and the whole target, mask the decoder so it can't cheat, and compute the loss for all output positions in parallel. Training is one expensive batch; inference is many cheap calls. The cost asymmetry between training and serving large language models is one of the dominant facts about how the modern AI industry operates.

Two architectural notes from the chapter so far worth surfacing here. **The encoder is a *parallel* reader**. Every encoder layer processes every source token simultaneously. The 2014 LSTM encoder this replaced did one token at a time. That parallelism is why the 2017 transformer trains 10&times; to 100&times; faster than the LSTM &mdash; not because the operation count is lower, but because GPUs love big parallel matrix multiplies and hate sequential dependency chains. **The decoder is *parallel* during training and *sequential* during inference**. During training, the masking trick lets you compute the entire output sequence's loss in one parallel pass. During inference, you have to do it one token at a time because each new token depends on the previous. This asymmetry is the architecture's main cost.

GPT, BERT, T5 &mdash; the entire modern family &mdash; descend from this picture. BERT keeps the encoder and discards the decoder; it is for understanding. GPT keeps the decoder and discards the encoder; it is for generation. T5 keeps both; it is for "everything is sequence-to-sequence." Each variant takes the same architectural primitives we just walked through and arranges them differently for a different task. The next and final act traces the family tree.
